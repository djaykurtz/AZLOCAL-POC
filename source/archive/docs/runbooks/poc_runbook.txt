# Azure Local POC - End-to-End Runbook

Clean execution sequence for a 6-node Azure Local POC in subscription
contoso-lab-sub, RG rg-azlocal-poc-001, hardware in lab
rack rack-01. The RG metadata location is westus3; Azure Local / Arc
control-plane resources use southcentralus per ADR 0001 and the validated
2026-06-04 Arc onboarding run.

This document is the "happy path" - what you do if everything works.
The discovery, dead-ends, and decision rationale live in the POC plan
and poc_prereq_checklist.txt. The external-role asks are summarized in
docs/prerequisites.md.

ASCII only. PowerShell-friendly (no backslash line continuations).

Status legend:
  [v]   Verified working in this POC (commands run, output captured)
  [p]   Planned, command shape known but not yet executed end-to-end
  [x]   Hands-off step (external team or smart hands does it)

# 1.2 - Create the POC resource group with the organizational tag schema.

# admins confirm it. Update it once known.

$providers = 'Microsoft.AzureStackHCI','Microsoft.Kubernetes','Microsoft.KubernetesConfiguration','Microsoft.ExtendedLocation','Microsoft.ResourceConnector','Microsoft.HybridContainerService','Microsoft.Attestation'
$providers | ForEach-Object -Parallel { az provider register --namespace $_ --consent-to-permissions 2>&1 | Out-Null } -ThrottleLimit 7

# 1.4 - Poll until all 7 show Registered (typically <5 min).
$providers | ForEach-Object { [pscustomobject]@{ Provider = $_; State = (az provider show --namespace $_ --query registrationState -o tsv) } } | Format-Table -AutoSize

APPENDIX - NODE REACHABILITY (AzVPN REQUIRED)
==============================================================================

# IMPORTANT - GSA routing gotcha (learned 2026-05-22):
# The 10.10.x.x address space is REUSED across multiple isolated L3 planes.
# GSA resolves lab.example.com DNS correctly, but direct-IPv4 traffic from GSA
# DOES NOT reach the lab nodes - it lands on unrelated corp hosts at the
# same address. TCP probes from GSA will appear to "succeed" on ports
# 22/443/3389/5985/5986 because some other machine answers, not the node.
#
# Always disconnect GSA and connect AzVPN before probing nodes by IP.
# Use FQDN + protocol handshake (Test-WSMan, SSH banner, browser HTTPS)
# rather than raw TCP connect for honest signal.

# Sanity: confirm DNS resolves all node + KVM names.
'azl-node-01.lab.example.com','azl-node-02.lab.example.com','azl-node-03.lab.example.com','azl-node-04.lab.example.com','azl-node-05.lab.example.com','azl-node-06.lab.example.com','kvm-01.lab.example.com' | ForEach-Object { $r = Resolve-DnsName $_ -ErrorAction SilentlyContinue; if ($r) { $ips = ($r | Where-Object IPAddress | Select-Object -ExpandProperty IPAddress) -join ','; "[OK]   $_ -> $ips" } else { "[FAIL] $_" } }

# Reachability check that survives the GSA proxy artifact.
# A fake port that reports "OPEN" is a proof that something between us
# and the destination is fabricating SYN-ACKs. Real listeners only
# respond on real ports.
$probeIPs = @('10.10.1.187','10.10.1.188','10.10.1.189','10.10.1.190','10.10.1.191','10.10.1.192')
$realPorts = @(22, 443, 3389, 5985, 5986)
$fakePort = 12345
$ProgressPreference = 'SilentlyContinue'
foreach ($ip in $probeIPs) {
  $line = "$ip :"
  foreach ($p in @($fakePort) + $realPorts) {
    $tc = New-Object System.Net.Sockets.TcpClient
    $task = $tc.ConnectAsync($ip, $p)
    $ok = $task.Wait(3000) -and $tc.Connected
    $line += "  $p=$(if($ok){'OPEN'}else{'-'})"
    $tc.Close()
  }
  $line
}
# If 12345 reports OPEN: you are still hitting a proxy. Verify VPN state.
# If 12345 is - and the real ports are OPEN: those are likely real.

# Honest WinRM check (uses FQDN, real protocol handshake, ignores TCP).
foreach ($n in 1..6) {
  $fqdn = "azl-node-{0:00}.lab.example.com" -f $n
  $r = Test-WSMan -ComputerName $fqdn -ErrorAction SilentlyContinue
  if ($r) { "$fqdn WSMan = $($r.ProductVersion)" } else { "$fqdn WSMan = no response" }
}
