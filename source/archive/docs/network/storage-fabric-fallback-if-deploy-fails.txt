CONTINGENCY OPTIONS (pull from these ONLY if deploy network validation fails)
-----------------------------------------------------------------------------
Option A - Untagged / access-port storage design (uses the PROVEN-GOOD path)
  Since untagged-over-native-711 already passed end-to-end (L2 + jumbo), deploy the
  storage fabric untagged instead of tagged:
    - Switch: set the storage ports to access mode -
        SW1 storage ports: switchport access vlan 711
        SW2 storage ports: switchport access vlan 712
    - Host / Network ATC: storage intent with NO storage VLAN (VLAN 0 / omit).
    - The switch handles VLAN membership; the host never tags -> sidesteps the tag issue.
  TO CONFIRM FIRST: that the Azure Local build in use accepts a storage intent without a
  storage VLAN ID (access-port topology). Check the deploy wizard / Network ATC intent
  options before proposing this to the network team.

Option B - Switch-side tag verdict (one read-only check, method-independent)
  While a tagged test holds traffic on the hosts, on the relevant switch:
     clear mac address-table dynamic
     show mac address-table vlan 711        (SW1)   / vlan 712 (SW2)
  - Host MACs 00-00-5E-00-53-01 (node01) / 00-00-5E-00-53-02 (node02) appear on the VLAN
    -> NIC is tagging, switch is learning -> forwarding problem between ports.
  - Absent -> NIC is not putting the 802.1Q tag on the wire (host/NIC-firmware side).
  Host tooling to hold traffic: scripts/Test-StorageFabricTagged.ps1 (add a hold if needed).

Option C - Silent-discard sweep on the switch (if B shows MACs learned but no forwarding)
     show interfaces EthernetX/1 counters errors
     show interfaces EthernetX/1 | include MTU|drops|discard
     show storm-control
  Look for input/output discards, CRC/errors, or broadcast/unknown-unicast storm-control
  suppressing the storage VLAN.

Option D - NIC firmware / VLAN offload (host side, if B shows no MACs learned)
  WinOF-2 manual (DRIVERS\NVIDIA WinOF-2 Documentation v26.4.50010.pdf, sec 3.3.3.9.1):
  "Facilities cannot be enabled if the firmware does not support this feature." Confirm
  the ConnectX-5 firmware supports vSwitch/SET VLAN offload; update WinOF-2/firmware if not.
  (Physical-adapter VLAN-ID property tagging is ConnectX-6 Dx+ only, so the SET/vSwitch
   path is the ONLY valid host tagging path on our ConnectX-5 - already using it.)

LESSON LOGGED
-------------
pktmon MAC filter captures the host's OWN egress frames (dst=peer MAC), so counting
peer-MAC frames on the sender is NOT proof of cross-switch delivery. Measure actual
replies (static ping) or capture RX-only on the receiver. The static ping is ground truth.
