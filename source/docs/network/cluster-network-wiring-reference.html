Rack rack-01 | Cluster nodes 01, 02, 04, 06 (node 03 = hot spare, node 05 = deferred) | Storage host data re-verified live against all four cluster nodes 2026-08-31. Storage networking is HEALTHY: 711 and 712 both forwarding tagged, RDMA enabled on every storage port, PFC priority 3 lossless confirmed.

This shows how each node's interfaces must connect and how the two top-of-rack switches must be configured. There are two independent planes: a routed management plane on the 1 GbE Broadcom ports, and two isolated storage fabrics on the 100 GbE Mellanox ports. Each storage port carries a SINGLE storage VLAN, tagged (802.1Q) - Port3 to the VLAN 711 fabric on sw1, Port4 to the VLAN 712 fabric on sw2. It is tagged rather than a plain access port only so PFC's 802.1p priority bits survive; it is not a multi-VLAN trunk. Match interfaces to switch ports by MAC. Management ports use OUI C4:CB:E1 (Broadcom). Storage ports use OUI 98:03:9B or B8:59:9F (both Mellanox; node 02 Port4 uses B8:59:9F after the 2026-07-24 card swap).

Storage IPs are not set on the switch. The host software (Network ATC) auto-assigns them at deploy time. For a switched deployment the Network ATC defaults are 10.40.1.0/24 on VLAN 711 and 10.40.2.0/24 on VLAN 712 (not the 192.168.71/72 switchless full-mesh values).

Critical rules

  1. Storage VLANs 711 and 712 must be tagged, never native, and each storage port carries only ONE of them. RoCEv2 lossless depends on PFC, and PFC uses the 802.1p priority bits carried inside the 802.1Q VLAN tag. A native (untagged) storage VLAN strips the priority and breaks lossless RDMA. Each port is a single-VLAN tagged port (sw1 = 711, sw2 = 712), not a multi-VLAN trunk. Keep native as the default unused VLAN 1.
  2. Jumbo on the switch, but check the hosts. L2 MTU 9214 on the storage ports gives headroom. As measured on 2026-08-31 the hosts are running 1514 / MTU 1500 on both storage adapters, not 9014, so the end to end path is standard frames. Storage is healthy and RDMA is up regardless, so this is a performance question rather than a correctness one. Decide deliberately whether to enable jumbo end to end.
  3. PFC on priority 3 plus ETS. These NICs are NVIDIA/Mellanox ConnectX-5, which are RoCE-only, and RoCE requires PFC and ETS. This is not optional.
  4. Both switches must be symmetric. sw1 carries the 711 fabric, sw2 carries the 712 fabric. Apply the same tagged-VLAN, jumbo, and PFC settings on both.
  5. Storage stays layer 2. No gateway, no routing, no IP on 711 or 712. Only VLAN 152 (management) is routed and is the path users and Azure use to reach the cluster.
  6. No link aggregation on storage ports. Do NOT put storage ports in a channel-group / LACP / port-channel. Azure Local uses Switch Embedded Teaming (switch-independent) with SMB Multichannel across the two separate storage VLANs; it does not use switch-side LAG. An LACP channel-group (mode active) will leave the member port suspended because the host never negotiates LACP on it.

   description azl-node-01
   mtu 9214

   switchport mode trunk
   switchport trunk allowed vlan 711        ! SW2 ports use 712
   dcbx mode ieee
   priority-flow-control on
   priority-flow-control priority 3 no-drop

   spanning-tree bpduguard enable
   no channel-group 9 mode active           ! REMOVE - no LACP on storage

Status as of 2026-08-31: storage networking is healthy. The 2026-07 fault is closed.

The failure this page was originally written to diagnose was 0 of 6 east-west on both storage VLANs. It was not switch port isolation and it was not the allowed-vlan list. On three of the four cluster machines the two Mellanox adapters were transposed, so the adapter carrying VLAN 711 was cabled to the switch serving 712 and the reverse. Node 02 was the only one wired the way the documentation described, which is why the pattern was hard to see.

It was corrected on the hosts with Rename-NetAdapter rather than by recabling the rack. Verified live on 2026-08-31 across nodes 01, 02, 04 and 06:

  • Port3 tagged VLAN 711 and Port4 tagged VLAN 712 on every node
  • RDMA enabled on all eight storage adapters
  • PFC enabled on priority 3 only, with an ETS SMB_Direct class at priority 3
  • Network ATC intents compute_management and storage both report Success and Completed on all four nodes
  • All four cluster nodes Up

Open item: the hosts are running standard frames on the storage adapters, not jumbo. See the MTU note above.
